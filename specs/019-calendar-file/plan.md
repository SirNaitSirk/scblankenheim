# Implementation Plan: Kalendereintrag für das Camp

**Branch**: `019-calendar-file` | **Date**: 2026-10-28 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/019-calendar-file/spec.md`

## Summary

A public route handler `GET /kalender/[campId]` returns an iCalendar file with one all day event per
camp (name, dates, location, website link, stable UID). A pure builder creates the file and a Google
Calendar template link. Both links are added to the confirmation mail, the teaser info mail and the
camp card of the participant page, only when the camp has valid dates.

## Technical Context

**Language/Version**: TypeScript 5, Next.js 16.4 App Router (route handler)

**Primary Dependencies**: none new. iCalendar text is generated by hand (RFC 5545 subset).

**Storage**: none. Reads `camps` (name, start_date, end_date, location) with the service role.

**Testing**: Vitest unit tests for the builder and link helpers, template tests for the mail links.

**Target Platform**: Vercel (Node runtime)

**Project Type**: Web application (single Next.js project)

**Constraints**: CRLF line endings, line folding at 75 octets, escaping of `\ ; , newline`, all day
`DTEND` exclusive (end date plus one day). No personal data (FR-003).

**Scale/Scope**: one camp per year.

## Research

- **R1 · Link instead of attachment**: The mail links to the route rather than attaching the file.
  Attachments raise mail size and spam scores, and a link always serves current dates (US1 scenario 4).
- **R2 · Google link in addition**: `https://calendar.google.com/calendar/render?action=TEMPLATE&text=…&dates=YYYYMMDD/YYYYMMDD&location=…&details=…`
  with the exclusive end date. Android opens a linked `.ics` inconsistently, Google's template link
  works everywhere.
- **R3 · Stable UID**: `camp-<campId>@<APP_URL host>`, `SEQUENCE` derived from nothing (0) and
  `DTSTAMP` = now; calendars that support updates match on UID.
- **R4 · Route path**: `/kalender/[campId]` (German public route like `/packzettel`), response
  `text/calendar; charset=utf-8`, `Content-Disposition: attachment; filename="<slug>.ics"`,
  `Cache-Control: no-store` so date changes show at once. Unknown id, invalid uuid, missing or
  inverted dates → 404 plain text "Nicht gefunden".

## Security requirements

- Route: uuid check before query; selects only `name, start_date, end_date, location`; no error
  details in the response.
- Builder escapes all text; no user supplied text other than admin camp fields.

## Acceptance criteria and checks

Spec US1 and US2. `npm run lint`, `npm test`, `npm run build`. Manual steps in
[quickstart.md](./quickstart.md).

## UI

- Mail: a framed text block "Trag dir das Camp gleich in den Kalender ein:" with two links
  "Apple oder Outlook" and "Google Kalender" (same quiet style as the 017 participant link).
- Participant page camp card: two outline buttons "In den Kalender" and "Google Kalender" in a row
  that wraps on small screens.
