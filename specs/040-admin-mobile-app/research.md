# Research: Admin am Handy und als Homescreen App

## R1 · Focus zoom on iOS

- **Decision**: 16px text for inputs, selects and textareas below `md`.
- **Rationale**: Safari on iOS zooms into any focused control whose computed font size is below
  16px. Raising the size fixes the cause and keeps pinch zoom for accessibility.
- **Alternatives**: `maximum-scale=1` in the viewport. Rejected, it disables user zoom for
  everyone and fails accessibility guidance.

## R2 · Manifest only for admin, and its scope

- **Decision**: static `public/admin.webmanifest`, linked through `metadata.manifest` in
  `app/admin/layout.tsx`; `start_url` `/admin`, `scope` `/`.
- **Rationale**: `app/manifest.ts` is linked from every page, which would change public pages.
  A static file is not matched by `proxy.ts` (`.webmanifest` is excluded), so iOS can fetch it
  without a Clerk session and during the prelaunch gate. The sign in page lives at `/sign-in`;
  with scope `/admin` the sign in redirect would leave the app.
- **Alternatives**: a route handler under `/admin`, rejected because the proxy protects it;
  scope `/admin`, rejected for the sign in reason above.

## R3 · Admin icon

- **Decision**: PNGs generated by `scripts/build-admin-icons.mjs` with `sharp` from an inline SVG
  monogram, committed. `app/admin/apple-icon.png` as nested file convention.
- **Rationale**: generated `apple-icon.tsx` routes have no file extension and would sit behind the
  Clerk proxy; a static `.png` is excluded by the matcher. A script keeps the icon reproducible
  like `scripts/build-camp-photos.sh`. Nested `icon` and `apple-icon` files are supported per
  segment; implementation verifies in the rendered `<head>` of `/admin` that only the admin
  `apple-touch-icon` is present. Fallback if both appear: move the public file to
  `app/(public)` style metadata on the root page only.
- **Alternatives**: hand made PNG, rejected as not reproducible.

## R4 · Status bar color

- **Decision**: `statusBarStyle: "default"`, `themeColor` by `prefers-color-scheme`, and the admin
  theme hook updates `meta[name=theme-color]` to the resolved theme.
- **Rationale**: `black-translucent` always draws white status text over the page, unreadable on the
  light topbar. With `default` current iOS versions tint the standalone status bar with the theme
  color. The user can override the system theme in the admin, so the meta tag must follow the
  stored choice, not only the media query. Verified on a device during the quickstart.
- **Alternatives**: `black` style, rejected because it is always black in light mode.

## R5 · Detecting standalone

- **Decision**: CSS media query `(display-mode: standalone)` as a Tailwind custom variant.
- **Rationale**: works in iOS home screen apps and Android installs, needs no JavaScript, renders
  the same markup on server and client.
- **Alternatives**: `navigator.standalone` in JS, rejected because it needs state after hydration
  and flickers.

## R6 · Reload

- **Decision**: `window.location.reload()`.
- **Rationale**: always fetches fresh data, also recovers from an error page or a lost
  connection. `router.refresh()` keeps a broken client state and gives no feedback offline.

## R7 · Offline

- **Decision**: no service worker.
- **Rationale**: data is live and personal, caching it on devices adds risk and maintenance for
  little gain. Excluded in the spec.
